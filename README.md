# phone-lead-bot

Telegram-бот, который собирает WhatsApp-номера для воронки «Pack de pronósticos» (тексты и юридические строки взяты с лендинга https://espack.lovable.app) и пишет лиды в Google-таблицу «Quiz leads».
Тексты на испанском (правятся в `texts.py`), номера нормализуются в E.164, без явного согласия ничего не сохраняется.

## Как работает диалог (2 действия + 1 необязательное)

1. `/start <tag>`: одно сообщение. Крючок («Gratis, en tu WhatsApp»), три пункта пака, **пример того, как выглядит пак** (помечен как иллюстративный), строка доверия («sin tarjeta, sin depósito, sin crear una cuenta»), затем согласие: пакет придёт **по WhatsApp**, это рассылка (прогнозы и предложения), отправитель (`BRAND_NAME`), ссылка на политику (`PRIVACY_URL`), `/borrar`. Кнопка «Tengo 18+ y acepto · Quiero mi pack» одновременно подтверждает возраст и согласие; время нажатия записывается. Кнопка «No» стоит отдельной строкой под ней.
2. Номер: кнопка «Usar mi número de Telegram» (принимается только свой контакт) или ввод руками. В тексте прямо сказано, что нужен номер **WhatsApp** (номер Telegram может отличаться), и что он используется только для сообщений в WhatsApp. Номер проверяется `phonenumbers`; без префикса считается испанским. После валидного номера лид сохраняется и уходит на webhook.
3. Сразу после номера: подтверждение с **названием отправителя** («de parte de …», чтобы первое сообщение в WhatsApp не выглядело от незнакомца) и необязательный выбор клуба одним касанием. Кнопка «Ver canal» стоит в этом же сообщении с самого начала (раньше она появлялась только после выбора клуба, и тот, кто клуб пропускал, канала не видел). Выбор клуба обновляет лид; webhook сработает второй раз, дедуплицируй по `tg_id`.

Необязательные строки доверия в приветствии включаются переменными `FREQUENCY_LINE` (например, «Máximo 3 mensajes por semana») и `PROOF_LINE` (например, «Más de 2.000 aficionados ya reciben el pack»). По умолчанию пусто. Включай только то, что правда: это обещания пользователю.

До нажатия «Acepto» и ввода номера в базу ничего не пишется. Версия формулировки (`CONSENT_VERSION` в `texts.py`, сейчас `es-tg-v3`) хранится в каждом лиде как доказательство того, с чем человек согласился. Меняешь дисклеймер, поднимай версию.

Пользователь может в любой момент написать `/borrar`, и его данные удаляются (право на удаление по GDPR).

## Команды администратора (ID из `ADMIN_IDS`)

- `/stats`: лиды всего и за 24 часа, разбивка по тегам и по клубам.
- `/export`: CSV со всеми лидами (открывается в Excel).

## Метки для A/B-теста объявлений

Ссылка на бота в Telegram Ads: `https://t.me/ИМЯ_БОТА?start=A1`. Допустимы символы `A-Za-z0-9_-`, до 64 знаков.

- `?start=A1` попадает в колонку `utm_content` (тег креатива).
- `?start=кампания__A1__ключ` (два подчёркивания) раскладывается в `utm_campaign`, `utm_content`, `utm_term`.

В `/stats` лиды группируются по тегу, в таблице те же значения лежат в utm-колонках, а в `landing_url` хранится ссылка, по которой человек пришёл.

## Запись в Google-таблицу «Quiz leads»

Бот пишет в ту же таблицу и в том же формате, что и веб-квизы (22 колонки). Колонки заполняются по названию в первой строке, поэтому порядок можно менять и добавлять свои.

| Колонка | Что пишет бот |
|---|---|
| `timestamp` | дата и время в формате `дд/мм/гггг чч:мм:сс` (часовой пояс `SHEET_TZ`, по умолчанию Europe/Madrid) |
| `lead_id` | UUID лида; по нему строка находится при обновлении и удалении |
| `quiz_id` | `QUIZ_ID` (по умолчанию `es_whatsapp_tgbot`) |
| `geo` | страна по номеру (ES) |
| `club`, `favourite_team` | `real_madrid`, `barca`, `atletico_madrid`, `other` (появляются, когда человек выбрал клуб) |
| `phone` | только цифры, как в большинстве строк: `34612345678` |
| `whatsapp_consent`, `consent` | `TRUE` (согласие даёт нажатие «Acepto») |
| `consent_text_version` | версия дисклеймера (`CONSENT_VERSION` в `texts.py`, сейчас `es-tg-v3`) |
| `utm_source` | `telegram`; `utm_medium`: `UTM_MEDIUM`; `utm_campaign`/`utm_content`/`utm_term` из тега |
| `brand`, `landing_url`, `referrer` | `BRAND_NAME`, ссылка на бота с тегом, `telegram` |
| `answers_json` | `{"flow":"telegram_bot","club":"barca"}` |
| `email`, `bet_frequency`, `fbclid` | пусто (бот их не собирает) |

Как это работает: лиды копятся в SQLite и каждые `SYNC_INTERVAL` секунд уходят в таблицу **одним пакетом** (200 лидов = один запрос, лимит Google API не страшен). Если Google недоступен, запись повторится позже. Строка находится по `lead_id`, поэтому дублей не бывает: выбор клуба обновляет ту же строку, а `/borrar` её удаляет.

Подключение:
1. Google Cloud Console: включи **Google Sheets API**, создай **Service Account** и скачай ключ JSON.
2. Открой таблицу, нажми «Настройки доступа» и дай `client_email` из ключа права **Редактор**.
3. В Render (Environment): `GSHEET_ID`, `GSHEET_GID` (значения для твоей таблицы уже в `.env.example`) и `GOOGLE_SERVICE_ACCOUNT_JSON` (весь JSON одной строкой). Либо загрузи ключ как Secret File и укажи `GOOGLE_SERVICE_ACCOUNT_FILE=/etc/secrets/sa.json`.
4. При запуске бот сам проверит доступ и остановится с ошибкой, если таблица недоступна или нет колонки `lead_id`.

Без Google Sheets можно обойтись: лиды остаются в SQLite (`/export` даёт CSV), либо можно слать на `WEBHOOK_URL` (Make.com).

## Запуск локально

```bash
pip install -r requirements.txt
cp .env.example .env   # заполнить BOT_TOKEN и ADMIN_IDS
export $(grep -v '^#' .env | xargs)
python bot.py
```

Тесты: `pytest -q` (проверяют валидацию номеров, базу и весь диалог на поддельной сессии Telegram, токен не нужен).

## Деплой на Render

Бот работает через long polling, поэтому на Render это **Background Worker** (порт не нужен). У воркеров нет бесплатного тарифа, и диск тоже только на платных сервисах. Не создавай его как Web Service: без открытого порта Render сочтёт деплой неудачным.

Быстрый путь: New, Blueprint, выбрать репозиторий. Render прочитает `render.yaml`, создаст воркер (Docker, регион Frankfurt, план Starter) и диск 1 ГБ в `/var/data`, и спросит три секрета: `BOT_TOKEN`, `ADMIN_IDS`, `GOOGLE_SERVICE_ACCOUNT_JSON`.

Вручную: New, Background Worker, Language Docker, затем Advanced, Add Disk с Mount Path `/var/data`, и переменные из списка ниже.

**Диск обязателен.** Без него файл SQLite стирается при каждом деплое и рестарте: пропадёт история лидов, а повторная регистрация создаст дубль в таблице. Если `DB_PATH` не на смонтированном диске, бот напишет предупреждение в логи при старте. Диск даёт ровно один экземпляр и несколько секунд простоя на деплой (старый экземпляр останавливается до запуска нового, поэтому конфликтов polling нет). Не запускай второй экземпляр с тем же токеном.

Что хранится только в памяти: состояние диалога (человек нажал «Acepto» и ещё не прислал номер). После рестарта такой человек получит «Escribe /start». Резервная копия лидов уже есть в Google-таблице.

### Переменные окружения

| Переменная | Обязательна | Значение |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `ADMIN_IDS` | да, чтобы работали `/stats` и `/export` | твой Telegram id (через @userinfobot), несколько через запятую |
| `DB_PATH` | да | `/var/data/leads.db` (внутри диска) |
| `BRAND_NAME` | да | настоящее название отправителя WhatsApp, показывается в согласии |
| `PRIVACY_URL` | да | ссылка на политику конфиденциальности |
| `GSHEET_ID`, `GSHEET_GID` | если нужна таблица | id и gid листа «Quiz leads» |
| `GOOGLE_SERVICE_ACCOUNT_JSON` | если нужна таблица | весь ключ сервис-аккаунта одной строкой (или `GOOGLE_SERVICE_ACCOUNT_FILE`) |
| `CHANNEL_URL` | нет | кнопка «Ver canal» |
| `FREQUENCY_LINE`, `PROOF_LINE` | нет | строки доверия в приветствии, только если правда |
| `UTM_MEDIUM` | нет | значение `utm_medium` для лидов |
| `WEBHOOK_URL`, `WEBHOOK_SECRET` | нет | дубль каждого лида в Make.com |
| `QUIZ_ID`, `UTM_SOURCE`, `DEFAULT_REGION`, `SHEET_TZ`, `SYNC_INTERVAL` | нет | есть значения по умолчанию, см. `.env.example` |

## Формат webhook

POST с заголовком `X-Webhook-Secret` (если задан `WEBHOOK_SECRET`):

```json
{"tg_id": 123, "username": "stan", "first_name": "Stan", "payload": "A1", "club": "Barça",
 "phone": "+34612345678", "age_confirmed": 1, "consent": 1, "consent_at": "2026-10-22T12:00:00+00:00",
 "consent_version": "es-tg-v3", "created_at": "...", "updated_at": "..."}
```

## Что нужно знать перед запуском трафика

- Не убирай слово WhatsApp из дисклеймера. Согласие действует только на то, что человеку прямо назвали, а WhatsApp Business требует opt-in именно на WhatsApp. Бот не проверяет, что номер зарегистрирован в WhatsApp.
- Заполни `BRAND_NAME` настоящим названием компании-отправителя и `PRIVACY_URL`. Без них дисклеймер неполный.
- Бот собирает только то, что нужно: номер, клуб, тег, Telegram id и username, время согласия. Хранить дольше нужного и передавать третьим лицам можно только в рамках политики конфиденциальности, на которую ведёт `PRIVACY_URL`.
- Рассылки по WhatsApp идут отдельно от бота. Следи за правилами WhatsApp (Business Policy) для рассылок про спорт и азартную тематику, иначе номер могут заблокировать.
- Бот не обещает выигрыша и не использует слов про ставки, но Telegram проверяет и бота. Не добавляй в `texts.py` ничего, что читается как гарантия результата.

## Тексты и юридические строки

Тексты бота повторяют лендинг: заголовок, три пункта пака (El pronóstico / La cuota / El porqué), иллюстративный пример пака, «Sin tarjeta, sin depósito y sin crear una cuenta», 18+ и «Ningún pronóstico garantiza un resultado». Всё редактируется в `texts.py`. Если меняешь то, что получает человек, обнови и дисклеймер, и `CONSENT_VERSION`. Бонус CaptainsBet с лендинга в бота намеренно не включён: это отдельное предложение с депозитом, и смешивать его с бесплатным паком нельзя.

## Что изменилось в версии es-tg-v3

- Приветствие: добавлен пример пака и более явный блок «бесплатно и без обязательств». Юридическая часть (WhatsApp, отправитель, /borrar, политика, 18+, «Ningún pronóstico garantiza un resultado») не тронута.
- Кнопка согласия стала продающей, но формулировка возраста и согласия сохранена; «No» вынесена в отдельную строку.
- Запрос номера уточняет «номер WhatsApp» (меньше невалидных для WhatsApp номеров из кнопки Telegram).
- Финальное сообщение называет отправителя и ведёт к каналу; число шагов не выросло.
- `requirements.txt`: добавлены `gspread` и `tzdata`. `sheets.py` импортирует `gspread` на верхнем уровне, без него контейнер падал при старте.

## Исправленные баги (проверка кода)

- Принимались стационарные (91x...) и бесплатные (800...) номера: для WhatsApp это пустые лиды. Теперь только мобильные.
- `/stats`: «за 24 часа» считал всё с начала вчерашней даты (сравнение строк ISO с форматом SQLite). Теперь точная граница.
- `BRAND_NAME` с `&` или `<` ломал HTML приветствия, и Telegram отклонял сообщение. Теперь экранируется (в таблицу уходит исходное название).
- Тег `/start <что угодно>` попадал в базу и в `/stats` как есть. Теперь только `A-Za-z0-9_-`, до 64 знаков.
- `/export`: имя из профиля Telegram вида `=HYPERLINK(...)` выполнялось бы как формула в Excel. Теперь экранируется.
- Двойной тап на «Acepto» перезаписывал время согласия и мог дважды задать вопрос про номер; стикер или фото в ожидании номера отправляли человека на «/start». Исправлено.
- Старая кнопка клуба после `/borrar` больше не говорит «gracias» без лида.
- Фоновые задачи (webhook, синхронизация с таблицей) держатся по ссылке: asyncio хранит на них только слабые ссылки.
- `CHANNEL_URL` вида `@канал` или `t.me/...` приводится к `https://...`: неверный URL в кнопке ронял сообщение после сохранения номера.
- `gspread` и `tzdata` добавлены в `requirements.txt` (без `gspread` контейнер падал при старте).
